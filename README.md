# Cera Functional Language - v1.0

**By Isaac Honeyman**

Cera is a strictly pure functional programming language featuring a Hindley-Milner type inference engine, built with a C# compiler frontend and a high-performance, deterministic C virtual machine backend (CeraVM)[cite: 7]. 

Designed to merge mathematical purity with modern readability, Cera replaces traditional functional syntax with an accessible C-family/OOP surface syntax[cite: 7].

## Core Features
* **Purely Functional:** Zero mutable state and zero side effects (excluding isolated compiler intrinsics for I/O)[cite: 7].
* **Hindley-Milner Type Inference:** Global functions require rigid type signatures, while local variables benefit from seamless, automatic type inference[cite: 7].
* **First-Class Functions:** Full support for higher-order programming, dynamic closures, and localized lambda expressions[cite: 7].
* **Algebraic Data Types (ADTs):** Custom recursive data structures and Sum Types seamlessly destructured via exhaustive pattern-matching `switch` expressions[cite: 7].
* **Tail Call Optimization (TCO):** $O(1)$ spatial complexity for unbounded recursive loops, preventing stack overflow exceptions during iterative algorithms[cite: 7].
* **Standalone Bytecode:** The C# compiler lowers `.cera` source files into a highly dense `.cerabc` Intermediate Representation, executed deterministically by the C-based CeraVM[cite: 7].

## Installation

Download the latest release archive for your operating system (Linux `.tar.gz` or Windows `.zip`). Extract the archive and run the included installation script (`install.sh` or `install.bat`). This automatically links the `cera` CLI wrapper to your global system path.

## Command Line Interface

The Cera toolchain is orchestrated via a unified CLI, seamlessly bridging the C# compiler and C Virtual Machine.

* `cera exec <file.cera> [args]` — The recommended workflow. Compiles the source file and immediately executes the generated bytecode.
* `cera build <file.cera> [flags]` — Compiles the source file into `.cerabc` bytecode inside the `Out/ByteCode/` directory without running it.
* `cera run <file.cerabc> [args]` — Directly executes a pre-compiled bytecode file on the Virtual Machine.
* `cera clear` — Cleans the workspace by deleting the `Out/` directory and all generated bytecode/dumps.

**Compiler Diagnostic Flags (`cera build`):**
* `-t, --tokens` : Dump the lexer token stream.
* `-a, --ast` : Dump the Abstract Syntax Tree.
* `-s, --analyzer` : Dump the semantic global environment.
* `-e, --emitter` : Dump the disassembled `.cerabc` bytecode.

## Quick Example

```c
import "Math.cera";

// ADTs and Pattern Matching
type tree<g> = Leaf | Node : (tree<g> * g * tree<g>);

def sumTree(t: tree<int>) : int = {
    switch (t) {
        Leaf -> 0,
        Node(left, val, right) -> val + sumTree(left) + sumTree(right)
    }
}

// Program Entry Point
def entry(args: char list arr): int = {
    var myTree = Node(Node(Leaf, 5, Leaf), 10, Node(Leaf, 15, Leaf));
    out("Tree sum: " :: intToChars(sumTree(myTree)));
    0; 
}
