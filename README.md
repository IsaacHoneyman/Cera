# Cera Functional Language - v1.2-0

**By Isaac Honeyman**

Cera is a strictly pure functional programming language featuring a Hindley-Milner type inference engine, built with a C# compiler frontend and a high-performance, deterministic C virtual machine backend (CeraVM). 

Designed to merge mathematical purity with modern readability, Cera replaces traditional functional syntax with an accessible C-family/OOP surface syntax. Version 1.1 introduced a highly optimised Directed Acyclic Graph (DAG) module system, FPU mathematics, and advanced structural pattern matching. 1.2 came with default values, multithreading a full FFI ecosystem, and more!

## Core Features
* **Purely Functional:** Zero mutable state and zero side effects (excluding isolated compiler intrinsics for I/O and hardware math).
* **Hindley-Milner Type Inference:** Global functions require rigid type signatures, while local variables benefit from seamless, automatic type inference.
* **DAG Module System:** $O(1)$ topological compilation caching with strict encapsulation boundaries using the `hidden` keyword.
* **Algebraic Data Types (ADTs):** Custom recursive data structures and Sum Types seamlessly destructured via exhaustive pattern-matching `switch` expressions.
* **Switch Guard Clauses:** Memory-safe "test-then-bind" pattern evaluation using `if (condition)` guards.
* **Tail Call Optimization (TCO):** $O(1)$ spatial complexity for unbounded recursive loops, preventing stack overflow exceptions during iterative algorithms.
* **Standalone Bytecode:** The C# compiler lowers `.cera` source files into a highly dense `.cerabc` Intermediate Representation, executed deterministically by the C-based CeraVM.

## Installation & Setup

The Cera toolchain is distributed as pre-compiled, self-contained binaries to ensure predictable deployment across diverse host operating systems.

**For Linux:**
1. Download and extract the `cera-v1.1-0-linux-x64.tar.gz` archive.
2. Open your terminal in the extracted folder.
3. Run the installation script: `./install.sh`.
4. Restart your terminal (or source your `~/.bashrc`) to ensure the global `cera` command is loaded into your system path.

**For Windows:**
1. Download and extract the `cera-v1.1-0-win-x64.zip` archive.
2. Open the extracted folder.
3. Double-click the `install.bat` script to run it.
4. Restart your Command Prompt or PowerShell to apply the new system PATH variables.

## Basic Usage Guide

Here is the standard workflow for writing, compiling, and executing your first Cera program.

**1. Create a Source File**
Create a new text file named `hello.cera` and add the required `entry` function:
```c
import "Math.cera";

def entry(args: char list arr): int = {
    out("Hello, Cera 1.1!");
    0;
}
```

**2. Build the Bytecode**
Compile your source code into executable Intermediate Representation (IR). This step automatically generates a `hello.cerabc` binary file inside an `Out/ByteCode/` directory:
```bash
cera build hello.cera
```

**3. Run the Virtual Machine**
Execute the generated bytecode on the CeraVM:
```bash
cera run Out/ByteCode/hello.cerabc
```

*(Alternatively, use the orchestration command `cera exec hello.cera` to build and run the file simultaneously!)*

## Full CLI Reference

The Cera toolchain is orchestrated via a unified CLI, seamlessly bridging the C# compiler and C Virtual Machine.

* `cera exec <file.cera> [args]` — Compiles the source file and immediately executes the generated bytecode.
* `cera build <file.cera> [flags]` — Compiles the source file into `.cerabc` bytecode without running it.
* `cera run <file.cerabc> [args]` — Executes a pre-compiled bytecode file on the Virtual Machine.
* `cera clear` — Cleans the workspace by deleting the `Out/` directory and all generated bytecode/dumps.
* `cera version` — Displays the current Cera version.
* `cera help` — Displays all Cera commands and flags.

**Compiler Diagnostic Flags (`cera build`):**
* `-v, --verbose` : Enable verbose compiler logging.
* `-t, --tokens` : Dump the lexer token stream.
* `-a, --ast` : Dump the Abstract Syntax Tree.
* `-s, --analyzer` : Dump the semantic global environment.
* `-e, --emitter` : Dump the disassembled `.cerabc` bytecode.
* `-d, --dump` : Enable all diagnostic dumps simultaneously.

**Virtual Machine Flags (`cera run`):**
* `-d` : Enable detailed Virtual Machine execution logging.
* `-f` : Dump Virtual Machine execution logs to a file.
* `-s` : Disable silent mode (forces standard log output).

## Quick Language Example

```c
import "Math.cera";

// ADTs and Pattern Matching
type tree<g> = Leaf | Node : (tree<g> * g * tree<g>);

// Optimized hot-path evaluation
inline def evaluateNode(val: int) : int = { val * 2; }

def sumTree(t: tree<int>) : int = {
    switch (t) {
        Leaf -> 0,
        Node(left, val, right) if (val > 0) -> evaluateNode(val) + sumTree(left) + sumTree(right),
        Node(left, _, right) -> sumTree(left) + sumTree(right)
    }
}

// Program Entry Point
def entry(args: char list arr): int = {
    var myTree = Node(Node(Leaf, 5, Leaf), -10, Node(Leaf, 15, Leaf));
    out("Tree sum: " :: intToChars(sumTree(myTree)));
    0; 
}
```
